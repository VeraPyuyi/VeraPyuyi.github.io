# Blog link previews on X and other social sites

Share the public article URL (`https://verapyuyi.github.io/blogs/<routeSlug>/` or its `/en/` counterpart), not the GitHub Markdown source or the blog index.

The article frontmatter remains the source of truth: `title`, `summary`, `cover`, and `coverAlt`. No per-article social tags need to be maintained manually. This change does not edit article text, routes, or original artwork.

## Image pipeline

`pnpm images:build` (also run by `pnpm build` and Pages CI) now creates a dedicated JPEG for every published local blog cover and the default site image. Originals remain intact. The full illustration is fitted inside a 1200 × 630 white canvas without cropping, flattened to JPEG, stripped of metadata, and checked against a 1 MB site budget. A content hash in the filename changes the image URL when its generated bytes change.

Generated files are `public/social/cover-<hash>.jpg` and `public/social-images.json`; do not commit them. The manifest connects each cover to its generated dimensions, MIME type, and URL, and lists the published blog routes. External cover URLs are left unchanged rather than fetched during the build. A fresh development checkout without a manifest falls back to the original cover URL.

`HeadMeta.astro` emits one `summary_large_image` card, absolute HTTPS image URLs for production, and image alt text, dimensions, and MIME type in the initial HTML. Chinese and English articles share the corresponding cover but retain their own titles and summaries.

## Verification

```sh
pnpm exec tsx --test tests/seo/*.test.mjs
pnpm build
python3 scripts/check-social-cards.py
python3 scripts/check-social-cards.py --live https://verapyuyi.github.io/
```

The output check reads every published blog page from the manifest, rejects duplicate or missing head tags, matches each card to its own article cover, checks canonical URLs, reads the generated JPEG headers and sizes, and checks robots rules. The Pages workflow runs this before upload. After deployment it requests all blog pages and their generated images with `Twitterbot/1.0`, checking HTTP delivery, MIME types, robots rules and the deployed revision.

This is a simulation using Twitterbot's user agent, not a request from X's own infrastructure. A passing test does not prove that X's internal cache has refreshed or that a particular account's composer has rendered the card. Verify the final platform appearance by pasting an article URL into a new X post draft; publishing is not necessary. A fresh query string can be tried for diagnosis of a previously shared URL, but should not be described as a guaranteed cache purge.

## Inspection before this change

The previous source already passed article covers to `HeadMeta` and declared `summary_large_image`; the configured robots settings did not disallow crawlers. The inspected article used its original 2,551,315-byte PNG directly for sharing. This is below the historically documented 5 MB X limit, so its size alone is not a confirmed root cause. The change reduces transfer size, adds explicit image metadata and makes failures detectable. The original user-reported X failure cannot be attributed conclusively without an actual X fetch result.
